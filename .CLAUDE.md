# Project

Personal Dictionary & Anki Application

The goal of this project is to create a lightweight personal application for vocabulary learning and Anki card generation.

The application will initially focus on English dictionaries and later support German dictionaries as well.

---

# Technology Stack

Backend:

- ASP.NET Core 10 (latest stable version)
- C#
- REST API
- Stop using port 5000 after finishing job/run.

Frontend:

- Angular 22 (latest stable version)
- TypeScript
- Standalone Components
- PrimeNG (compatible version) when's possible
- While running or debuging don't use port 4200

Integration:

- AnkiConnect

---

# Project Goals

The application should allow users to:

- Search for a word.
- Query multiple dictionary providers.
- Display dictionary data in a unified UI.
- Select meanings.
- Select individual examples.
- Add custom translations or notes.
- Preview the final Anki card.
- Select Anki deck and note type.
- Create notes through AnkiConnect.

The application is intended for personal use and maintainability is more important than supporting every possible feature.

---

# Architecture Principles

Dictionary providers must be isolated behind a common abstraction.

Do not couple the application domain model to any specific dictionary provider.

Examples of providers:

- Longman
- Oxford
- Cambridge
- Duden
- DWDS
- Future providers

Each provider is responsible for fetching and parsing its own source format.

The rest of the application must operate on normalized models.

---

# Dictionary Model

The domain model should support:

- Language
- Word
- Pronunciation
- Phonetics
- Audio
- Part of speech
- Meanings
- Examples
- Dictionary metadata

The model must be designed so English and German can be supported without redesigning the application.

---

# Card Generation

The application must support:

- Card preview inside Angular
- Card generation for Anki

Preview and final Anki cards should be generated from the same rendering system whenever possible.

Avoid maintaining separate rendering logic for preview and Anki output.

---

# Anki Integration

Use AnkiConnect.

The backend has no knowledge of Anki or AnkiConnect. Angular calls AnkiConnect directly.

Flow:

Angular → AnkiConnect → Anki

The backend is only responsible for dictionary lookups.

---

# Development Style

Keep the project pragmatic.

Avoid:

- Microservices
- CQRS
- Event sourcing
- Over-engineering
- Premature abstractions
- Unnecessary interfaces

Prefer:

- Simplicity
- Readability
- Strong typing
- Clear naming
- Small focused classes
- Testable code

---

# Testing

Dictionary parsers should be tested using saved HTML fixtures.

Avoid network access during parser unit tests.

Changes to dictionary parsing logic should include tests whenever practical.

---

# Workflow

Before implementing a non-trivial task:

1. Inspect the relevant code.
2. Explain the proposed approach.
3. Implement the smallest reasonable change.
4. Build and test the affected area.
5. Review the result.

Do not make large unrelated changes in a single task.

Prefer incremental development.

When requirements are unclear, ask for clarification instead of making large assumptions.
